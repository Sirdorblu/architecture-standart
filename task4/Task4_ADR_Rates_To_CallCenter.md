# ADR: Передача депозитных ставок в кол-центр и партнёрский кол-центр (MVP)

**Статус:** proposed  
**Версия:** 10  
**Дата:** 2025-10-24  
**Автор:** Архитектура цифровой трансформации

---

## Контекст
Маркетинговая кампания увеличит звонки Операторам КЦ и партнёрского КЦ нужны актуальные ставки Партнёр получает только файлы, API недоступны Требуется решение в рамках MVP без ломки АБС и с минимальными изменениями в ИБ

## Use Cases

| № | Действующие лица/системы | Use Case | Описание |
|:-:|:-|:-|:-|
| UC1 | Оператор КЦ, Система КЦ, АБС | Просмотр актуальных ставок в КЦ | КЦ запрашивает ставки по API внутреннего сервиса справочников, в интерфейсе видит тарифную сетку и дату актуальности |
| UC2 | БО депозиты/кредиты, АБС | Поддержание ставок | Редактирование ставок и их периодов действия в АБС (или модуле ставок) с ролевым разграничением |
| UC3 | Партнёрский КЦ, Шлюз выгрузки | Получение файла со ставками | Партнёр получает файл (CSV) по расписанию на e‑mail с криптографической подписью и/или шифрованием, сверяет контрольную сумму, загружает в свою систему |
| UC4 | Сайт/ИБ, Сервис заявок | Консистентность ставок фронтов | Фронты кэшируют и показывают те же ставки/периоды, что и КЦ, из единого источника |
| UC5 | Аудит, Безопасность | Отслеживание изменений ставок | Журналирование всех изменений ставок и выгрузок файлов, возможность расследования инцидентов |

## Нефункциональные требования (выжимка)
- Транспортная защита TLS 1.2+/1.3  
- Формат файла — CSV, контрольная сумма SHA‑256 в сопроводительном `sha256`  
- Безопасная доставка файла партнёру: PGP для подписи, дублирование контрольной суммы в теле письма  
- Доступность: внутренняя API‑ручка со ставками p95 ≤300 мс, расписание выгрузки партнёру не реже 1 раза/сутки, по событию — сразу  
- Идемпотентность выгрузок: версия/валидность, дата‑штамп, политика замены  
- Наблюдаемость: метрики успешных/ошибочных выгрузок, алерты  
- Совместимость со стеком: Java/Spring для сервисов, Oracle (АБС), MS SQL при необходимости кеша, очереди — Kafka в целевой модели

## Решение (концепт)
1 **Единый источник ставок** — модуль ставок в АБС остаётся системой записи  
2 **Сервис «Справочник ставок» (внутренний)** — Spring Boot, читает ставки из АБС через адаптер, отдаёт read‑only API для КЦ/ИБ/Сайта, кэш на 5-15 мин  
3 **Шлюз выгрузки партнёру** — батч‑процесс: формирует `rates_YYYYMMDDcsv` + `rates_YYYYMMDDcsvsha256`, подписывает письмо (PGP), отправляет на адрес партнёра  
4 **Система КЦ** — добавляет экран «Ставки» и периодический pull к внутреннему API  
5 **Контроль целостности** — партнёр проверяет SHA‑256, при расхождении — отказ от загрузки и уведомление  
6 **Аудит и логирование** — журнал изменений ставок в АБС, журнал всех выгрузок и доставок в шлюзе

### Причины выбора
- CSV широко совместим и формально описан  
- TLS — безопасность в транзите
- Электронная почта с S/MIME или OpenPGP — стандартная криптография для файловых сценариев без API  
- SHA‑256 — общепринятый стандартный хеш  
- Kafka — целевая шина событий для последующего «push при изменении»

## Альтернативы
- SFTP с сервером партнёра — отклонено, партнёр не поддерживает API‑подключения  
- Веб‑портал для ручной выгрузки — опционально как резервный канал, но усложняет UX  
- Рассылка Excel — удобно для людей, но ненадёжно и неоднозначно, CSV предпочтительнее

## Риски и ограничения
- Почтовая доставка может задерживаться/фильтроваться, требуется мониторинг и дублирование на резервный адрес  
- Расхождения при кэшировании фронтов и КЦ — нужно единое TTL и версионирование  
- Криптография писем требует управления ключами и регламентов ротации
